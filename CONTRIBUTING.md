# Как внести вклад в Draftline

Спасибо за интерес к проекту. Ниже — короткий порядок работы.

## Сборка и тесты

```powershell
dotnet restore Draftline.slnx
dotnet build Draftline.slnx -c Release
dotnet test --solution Draftline.slnx -c Release
```

Требуется .NET SDK 10.0.400 или новее (см. `global.json`). Сборка не должна давать предупреждений,
все тесты (`tests/`) должны проходить, синтаксис JavaScript проверяется через `node --check`
(см. [Разработка](docs/ru/development.md)).

## Структура

`Draftline.slnx` объединяет редактор `src/Draftline.App`, тему `src/Flare.Theme.OneC` и тесты
`tests/Draftline.App.Tests`. Внутри приложения: `Model` — домен и геометрия, `Services` — сессия,
история, хранение и экспорт, `Components`/`Pages` — интерфейс, `Theming` — оформление макета.

## Правила

- Команды над документом проходят через `DocumentSession`, чтобы попасть в историю и автосохранение.
- Изменение формата документа — только вместе с новой версией схемы, миграцией и тестом на старый файл.
- Компоненты и токены берутся из Flare; собственный CSS и JS держатся минимальными. Чего не хватает
  в самой библиотеке, то предлагается в [Flare](https://github.com/jrfrigat/Flare).
- Тесты пишутся на поведение.
- Тексты интерфейса — на русском.
- Комментарии объясняют «почему», а не пересказывают код.

## Pull request

1. Ветка от `main`.
2. Сборка без предупреждений и зелёные тесты.
3. В описании — что изменилось и как проверено (для интерфейса — в каком браузере).

## Сообщения об ошибках

Приложите шаги воспроизведения, ожидаемое и фактическое поведение, браузер и его версию и, если
возможно, JSON макета (без чувствительных данных) и сообщения консоли.
